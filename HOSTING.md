# Облачное размещение журнала

Проект подготовлен для управляемого хостинга Sites с постоянной базой Cloudflare D1. Его идентификатор сохранён в `.openai/hosting.json`; повторно создавать площадку для этого проекта не нужно.

Выделенный адрес площадки:

`https://classjurnal-olgakonko2477.leafy-fern-1659.chatgpt.site`

Сам факт выделения адреса не означает завершение публикации. Работоспособность подтверждается после успешного развёртывания и проверки `/health`, `/api/state` и страницы в браузере.

## Как устроена облачная версия

- `worker/index.js` обслуживает интерфейс и API без пароля.
- `lib/cloud-store.js` сохраняет сущности журнала в таблицах D1.
- Правила уроков, посещаемости, оценок и шаблонов общие с локальной версией.
- Запись нескольких связанных изменений атомарна. Проверка версии защищает от перезаписи правок с другого устройства.
- Перед восстановлением JSON сохраняется предыдущее состояние. Последние 10 таких копий доступны в настройках облачного журнала.
- Excel и печать/PDF доступны так же, как локально.
- Облачная версия не зависит от включённого домашнего компьютера.

Локальная SQLite и облачная D1 — разные базы. При первом размещении существующие данные переносятся через JSON-копию. После перехода пользуйтесь облачным адресом на обоих устройствах: локальные записи не синхронизируются с облаком автоматически.

## Сборка и проверки

```sh
npm ci
npm test
npm run build
npm run test:cloud
```

Браузерная проверка облачной версии в PowerShell:

```powershell
$env:JOURNAL_TEST_CLOUD='true'
npm.cmd run test:browser
```

На Linux:

```sh
JOURNAL_TEST_CLOUD=true npm run test:browser
```

Сборка создаёт `dist/server/index.js`, конфигурацию Worker и `.openai/hosting.json`. В архив публикации включается только `dist`, без рабочей базы, паролей, `node_modules` и тестовых данных. Служебный идентификатор D1 в конфигурации локальной сборки — заглушка; постоянную базу выделяет Sites для привязки `DB`.

Загрузка исходников должна предшествовать сохранению версии. Публикуется именно версия с SHA загруженного коммита. Секрет доступа к репозиторию Sites используется только на время команды Git и не сохраняется в файлах или Git-конфигурации.

Вход без пароля выбран и подтверждён пользователем. Для такого доступа аудитория опубликованного сайта должна быть `public`; одного отключения формы входа внутри приложения недостаточно, если сама площадка требует авторизацию.

## Резервирование

Регулярно скачивайте полную JSON-копию через «Настройки → Скачать копию». Excel/PDF не заменяют полную копию. Восстановление принимает тот же формат, что локальная версия. Для больших объёмов действует предел облачного хранилища на один передаваемый раздел; приложение сообщит о превышении до применения изменений.

Не используйте браузерные сквозные тесты на опубликованном адресе с реальными данными: они предназначены для отдельной временной базы. Проверка опубликованного сайта должна сохранять пользовательские записи.
