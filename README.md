# Классный журнал

Личный журнал школьного учителя с общими данными для компьютера и телефона. Интерфейс на русском языке. Данные сохраняются на сервере в SQLite, а не в браузере. Журнал открывается напрямую, без пароля, на обоих устройствах. Любой, кто может открыть адрес сайта, может просматривать и изменять записи.

## Что работает

- Учебные годы и четыре четверти с настраиваемыми границами.
- Классы, добавление учеников списком, поиск, исправление имени и архивирование.
- Несколько предметов в каждом классе.
- Таблица журнала по месяцам и четвертям, закреплённые фамилии и даты.
- Несколько оценок за урок, независимая посещаемость, очистка и исправление записей.
- Дата, время, тема и домашнее задание каждого урока.
- Режим «Один урок» с удобным вводом на телефоне.
- Календарь на неделю/месяц, список уроков дня.
- Еженедельное расписание с разным временем по дням, диапазоном дат и предпросмотром.
- Предупреждение о пересекающихся уроках.
- Исключение ученика из будущего расписания без удаления шаблона.
- Удаление шаблона с сохранением истории и заполненных будущих уроков.
- Excel с двумя листами и печать / сохранение PDF с разбиением широкой таблицы.
- Скачивание резервной копии и восстановление через настройки.
- Защита от перезаписи изменений, внесённых с другого устройства.

## Быстрый запуск на этом компьютере

Нужен Node.js 24 или новее. В PowerShell, в папке проекта:

```powershell
npm.cmd ci
npm.cmd start
```

Откройте **http://localhost:3000**. Журнал откроется сразу, без регистрации и пароля.

Если зависимости уже установлены, достаточно `npm.cmd start`. Для остановки нажмите Ctrl+C в окне сервера.

Это локальный запуск для проверки. Адрес `localhost` на телефоне указывает на сам телефон, поэтому для общего доступа используйте размещение по HTTPS, описанное ниже.

## Первое заполнение

1. Нажмите «Настроить учебный год». Проверьте предложенные даты четвертей по календарю своей школы.
2. Добавьте класс, например «5А».
3. Добавьте предметы класса.
4. Добавьте учеников списком: одно Ф. И. О. в строке. Для пришедших позднее укажите дату зачисления.
5. Откройте «Журнал». Добавьте отдельный урок или настройте повторение в «Расписании».
6. Нажмите на ячейку ученика, чтобы внести посещаемость и оценки. Оценки вводятся через пробел: `5 4`.
7. Нажмите дату урока, чтобы заполнить тему и ДЗ. На телефоне удобен режим «Один урок».
8. Для выгрузки выберите класс, предмет и период, затем нажмите «Выгрузить».

Обозначения: **П** — присутствовал, **Н** — отсутствовал, **Б** — болел, **У** — уважительная причина. Точка означает, что записи ещё нет. Прочерк означает, что ученик не участвует в уроке.

## Одновременная работа с телефона и компьютера

Откройте один адрес сайта на обоих устройствах. В открытом журнале изменения с другого устройства проверяются каждые 30 секунд, когда вы не редактируете форму. Можно нажать «Обновить» вручную.

Если другой сеанс изменил журнал, пока вы заполняли форму, сохранение остановится с пояснением. Введённые значения останутся в форме. Проверьте обновлённые данные и повторите сохранение. Работа без связи с сервером не поддерживается.

После перезапуска сервера журнал продолжит открываться без пароля; данные сохраняются.

## Правила сохранения истории

- «Убрать ученика» в карточке расписания исключает его начиная с указанной даты. Ученики класса, уроки остальных и шаблон остаются.
- Архивирование прекращает участие ученика во всех уроках класса с выбранной даты.
- Исключение и архивирование не удаляют ранее внесённые отметки.
- «Удалить шаблон» удаляет только его будущие пустые уроки. Урок считается будущим, если его начало позже текущего времени в часовом поясе журнала.
- Прошедшие уроки и уроки с темой, ДЗ, оценками или посещаемостью остаются самостоятельными записями.
- Переносы серий, сложные исключения и автоматические итоговые оценки не реализованы в соответствии с заданием.

## Размещение на VPS/VDS

Подготовлены `Dockerfile`, `compose.yaml` и `Caddyfile`. Развёртывание требует сервера, домена и доступа администратора; само по себе наличие этих файлов не означает, что сайт опубликован.

Для готовой конфигурации нужны:

- Linux-сервер с Docker и Docker Compose;
- отдельный домен или поддомен, направленный на IP сервера;
- доступные порты 80 и 443 для HTTPS;
- постоянное дисковое хранилище для базы.

Если на сервере уже работает сайт или reverse proxy, не запускайте второй сервис на тех же портах: используйте существующий прокси и передайте ему запросы к контейнеру журнала. Обычный PHP-хостинг без поддержки Node.js/контейнеров для этого приложения не подходит.

### Установка с Docker Compose

1. Загрузите исходники проекта на сервер. Не переносите `node_modules`, тестовые файлы из `test-results` и чужие данные.
2. В папке проекта создайте `.env`:

```dotenv
JOURNAL_DOMAIN=journal.example.ru
REQUIRE_PASSWORD=false
```

Укажите настоящий домен без `https://`, пути и завершающего слеша. Ограничьте доступ к `.env` средствами сервера и не добавляйте его в Git.

3. Выполните:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 journal caddy
```

4. Откройте `https://ВАШ_ДОМЕН` с компьютера и телефона. Внесите пробную запись, проверьте её на втором устройстве и после перезапуска контейнера.

Приложение слушает внутренний порт 3000; наружу опубликованы только порты HTTPS-прокси. База лежит в постоянном томе `journal_data`. Обычное обновление контейнера не удаляет данные. Команда `docker compose down -v` удаляет тома вместе с журналом — не используйте её для обновления.

В Docker Compose прямой вход без пароля включён явно. Существующие записи и ранее сохранённый хеш пароля не удаляются.

### Хостинг с Node.js без Docker

Укажите команду запуска `node server.js`, установку `npm ci --omit=dev` и Node.js 24+. Задайте:

```dotenv
HOST=0.0.0.0
PORT=3000
DATA_DIR=/постоянный/каталог/журнала
PUBLIC_ORIGIN=https://journal.example.ru
COOKIE_SECURE=true
REQUIRE_PASSWORD=false
```

Настройте HTTPS перед приложением и постоянный диск для `DATA_DIR`. `PUBLIC_ORIGIN` должен точно совпадать с адресом сайта, без завершающего слеша. Не размещайте базу в каталоге, содержимое которого раздаётся посетителям как статические файлы.

Приложение рассчитано на **один серверный процесс** с одним диском SQLite. Несколько независимых реплик или бессерверный хостинг с временной файловой системой не поддерживаются этой конфигурацией.

## Резервные копии

В интерфейсе: **Настройки → Скачать копию**. Файл содержит весь журнал без пароля и сеансов входа. Храните копии вне сервера. Excel/PDF — отчёты, а не полные резервные копии.

Восстановление: **Настройки → Выбрать файл копии**. Выберите JSON и введите `ВОССТАНОВИТЬ`. Перед заменой текущие данные автоматически сохраняются в `DATA_DIR/before-restore-<время>.json`. Этот файл можно забрать с сервера и восстановить таким же способом.

Для регулярного автоматического резервирования можно запускать:

```sh
node --env-file-if-exists=.env scripts/backup.js /путь/к/копиям/journal-2026-09-20.json
```

Скрипт не перезаписывает существующий файл. Для ежедневных копий задавайте новое имя и настройте расписание средствами сервера. Восстановление через сайт принимает файлы до 12 МБ. Для большего архива понадобится административное восстановление базы.

Для резервирования файла SQLite напрямую сначала остановите приложение или используйте SQLite backup API; не копируйте только `journal.sqlite` при работающем сервере, игнорируя WAL.

## Необязательный режим с паролем

По запросу пользователя режим с паролем отключён по умолчанию. Если позднее понадобится защита, администратор может установить `REQUIRE_PASSWORD=true` (для Docker — изменить значение в compose.yaml). Следующие команды относятся только к этому дополнительному режиму.

Нужен доступ к серверу. Остановите приложение, задайте новый `JOURNAL_PASSWORD` в `.env`, затем выполните:

```sh
node --env-file-if-exists=.env scripts/reset-password.js
```

Для Docker при остановленном сервисе:

```sh
docker compose stop journal
docker compose run --rm journal node scripts/reset-password.js
docker compose up -d journal
```

Перезапуск необходим для завершения всех старых сеансов. Данные журнала не меняются.

## Проверки разработки

```powershell
npm.cmd test
npm.cmd run test:browser
```

Первый набор — 18 проверок правил журнала, SQLite, HTTP API, доступа и XLSX. Второй — сквозная проверка в браузере Microsoft Edge: настройка с нуля, 30 вымышленных учеников, повторы, отметки, перезагрузка, периоды, XLSX/PDF, два сеанса и экраны 360/390 px. На машине без Edge установите браузер Playwright и адаптируйте `BROWSER_CHANNEL`/параметры запуска в `tests/browser.mjs`.

Тесты создают отдельные временные базы и не используют ваш рабочий журнал. Снимки экранов и примеры выгрузки с вымышленными данными сохраняются в `test-results/`.

## Структура

- `server.js` — HTTP, вход, сеансы, API и файлы интерфейса.
- `lib/domain.js` — правила расписания, учеников, отметок и периодов.
- `lib/store.js` — отдельные таблицы сущностей SQLite, транзакции, версии, копии.
- `lib/export.js` — Excel.
- `public/` — адаптивный интерфейс без внешних шрифтов, CDN и аналитики.
- `tests/` — автоматические и браузерные проверки.
- `references/` — исходные изображения бумажного журнала.

Технические справочники: [Node.js SQLite](https://nodejs.org/api/sqlite.html), [ExcelJS](https://github.com/exceljs/exceljs). Для ExcelJS зафиксирована исправленная транзитивная версия UUID через `overrides`; выгрузка проверена тестом чтения полученного XLSX.
